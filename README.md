# SIMS — Supermarket Inventory Management System (by FORZA)

A simple web app for the CCPGLANG project: products and categories, stock on hand,
a full stock-movement log, suppliers and purchase orders, sales, users, and a dashboard
with the low-stock and stock-value reports.

It enforces the same rules described in the paper:

| Rule | Where |
|---|---|
| Stock can never go below zero | `_apply_movement` in `db/core.sql` |
| Every stock change writes the balance **and** the log together (one function, one transaction) | `_apply_movement` |
| On-hand quantity = sum of its movements (signed `quantity_delta`, 7 movement types) | `stock_movements` table |
| Only active users can record movements; inactive users can't sign in | `_actor()` |
| A product with movements can't be deleted; users/suppliers are deactivated, not deleted | `delete_product`, `set_*_active` |
| Prices are exact decimals (`numeric(12,2)`), never floats | all tables |
| SKU auto-generated as `SMS-XXXXXXXX`; barcode must pass the EAN-13 checksum | `save_product` |
| Purchase orders only for active suppliers; only pending orders can be edited/received/cancelled; receiving adds stock-in for each line | `*_purchase_order` |
| A sale checks every line first, so one that fails on its last item changes nothing | `create_sale` |

With the sample data the dashboard shows **Rice 5 kg** and **Orange Juice 1 L** as low on stock
and a stock value at cost of **₱2,365.00**, matching the report.

## Two modes (no code changes needed)

- **Demo mode (default):** if no Supabase keys are set, the app runs a real PostgreSQL database
  *inside the browser* (PGlite) with the same SQL. Data is saved in that browser.
  Sign in with **EMP-0001 / sims123**. (EMP-0002 is a deactivated account, to show it gets refused.)
- **Supabase mode:** set the two environment variables below and all data is shared in your Supabase database.

## Deploy to Vercel

1. Push this folder to a GitHub repo.
2. On vercel.com → **Add New → Project** → import the repo. Vercel detects Vite automatically
   (build: `npm run build`, output: `dist`). Click **Deploy**.
3. That's it for demo mode.

## Optional: connect Supabase

1. Create a project at supabase.com.
2. **SQL Editor → New query** → paste all of `supabase/setup.sql` → **Run**.
   (Creates the tables, rules, sample data, and locks the tables so the browser can only use the functions.)
3. **Authentication → Users → Add user → Create new user**: enter an email + password and tick
   **Auto Confirm User**. Each user gets a SIMS account automatically (Employee ID `EMP-1001`, `EMP-1002`, …).
   You can rename them / change Employee IDs on the app's **Users** page.
   Tip: to choose the name and ID up front, add user metadata `{"name": "Juan Tamad", "employee_id": "EMP-0001"}`.
4. **Project Settings → API**: copy the *Project URL* and the *anon public* key.
5. In Vercel → your project → **Settings → Environment Variables**, add
   `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`, then **Deployments → Redeploy**
   (Vite reads these at build time, so a redeploy is required).

Staff can sign in with either their Employee ID or their email.

## Run locally

```bash
npm install
npm run dev          # http://localhost:5173 (demo mode)
npm test             # 13 tests of the SQL rules (runs PostgreSQL in-process, no Docker)
```

For Supabase locally, copy `.env.example` to `.env` and fill in the two values.

## Project layout

```
db/core.sql          tables + all business rules as SQL functions (used by both modes)
db/seed.sql          sample data
db/demo.sql          demo-mode accounts
db/supabase.sql      Supabase-only: row-level security, grants, auth.users trigger
supabase/setup.sql   = core + seed + supabase, generated by `npm run build:sql`
src/lib/api.ts       picks Supabase or demo backend; every action is one SQL function call
src/lib/reports.ts   low stock, stock value, totals (in centavos, no float errors)
src/pages/           Landing, Login, Dashboard, Inventory, Suppliers, Sales, Stock Log, Users
tests/               rule tests + a test that installs setup.sql in a Supabase-like database
```

If you edit anything in `db/`, run `npm run build:sql` so `supabase/setup.sql` stays in sync.
In demo mode, use the user menu → **Reset demo data** to start over.
